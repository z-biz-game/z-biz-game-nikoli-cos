# 纸上逻辑 Nikoli

浏览器原生的纸笔推理谜题合集：**数织 / 数链 / 点灯 / 孔明棋 / 数墙 / 帐篷 / 黑白 /
隔离 / 五寸钉 / 数间 / 数邻**。十一种玩法各带一个唯一解生成器和一个真求解器 —— 提示不是写死的剧本，
而是当场推出来的那一步。

零构建、零运行时依赖、零美术与音频文件：打开 `index.html` 需要的那点东西全在
`js/` 里，Canvas 2D 画棋盘，WebAudio 合成音效，localStorage 存进度。

```bash
node tools/serve.mjs        # → http://127.0.0.1:5173/，然后点开任一档位
node --test test/*.test.mjs # 259 项引擎单测（不开浏览器）
bash tools/verify.sh        # 单测 + 无头 Chrome 真指针通关，一把梭
```

> 直接双击 `index.html` 不行：裸 ES Module 在 `file://` 下会被 CORS 挡掉，必须有 http://。

## 十一种玩法

| 玩法 | 档位 | 生成器保证 | 提示怎么来的 |
| --- | --- | --- | --- |
| 数织 Nonogram | 5×5 / 7×7 / 10×10 / 12×12 / 15×15 | 只靠线推理就能推到底，不需要猜 | 逐行逐列做交集推理，卡住时才做反证 |
| 数链 Number Link | 4×4 / 5×5 / 6×6 | 哈密顿路径切段，且枚举确认过唯一解 | 交出唯一解里的一格，而不是整条答案 |
| 点灯 Lights Out | 4×4 / 5×5 / 6×6 / 7×7 | 由按压集合倒推盘面，一定可解；按压数落在该档区间内 | GF(2) 上解出全部解，取最短的那一步 |
| 孔明棋 Peg Solitaire | 25 孔小十字 / 33 孔英式 / 37 孔法式 | 从"只剩一子"的终局倒放生成，天然有解；中心空、且现搜够快 | 在原路线上照本宣科；走偏了现搜 DFS + 死局记忆 |
| 数墙 Nurikabe | 7×7 / 8×8 / 10×10 | 带计数的求解器数过解数（数到第二种就早停；预算烧完报 `capped` 并丢题） | 拿"全盘还要几滴墨"算账，交出逻辑上被逼定的那一格 |
| 帐篷 Tents | 6×6 / 8×8 / 10×10 | 按"每棵树恰配一顶"生长，六条规则推到不动点后再枚举复核 | 六条规则的下一手：该搭的搭、该封的整行封 |
| 黑白 AKBANE | 6×6 / 8×8 / 10×10 | 从满标数盘一条条擦数，每擦一个都穷尽数过解数才放行 | 先擦掉与唯一解冲突的那格，再给被逼定的那格 |
| 隔离 Hitori | 6×6 / 8×8 / 10×10 | 先摆合法黑盘、再用二分图匹配反推数字盘；缝不出题面就换盘 | 交出"哪一个解里它都必是黑格"的那一枚 |
| 五寸钉 Slant | 6×6 / 8×8 / 10×10 | 先画满斜线再数交点，数字天生来自某个真解；删数后每一刀都用铅笔路径重证唯一 | 先擦掉与推导冲突的斜线，再交逼定的那一笔 |
| 数间 Shikaku | 6×6 / 8×8 / 10×10 | 随机切盘再合并邻块；交出的盘既要纯规则推到底（零反证），又要独立枚举数到恰好一种分法 | 先擦掉塞不进任何一种摆法的墨，再交"唯一归属/全线穿透/区域锁定"的下一手 |
| 数邻 Dominosa | 4×5 / 6×7 / 8×9 | 种一套铺满全盘的骨牌、把每个无序数对（含双数）一一分配过去，再对调数字，每调一次都用带计数的求解器数过解数 —— 数到第二种就丢题，预算烧完（`capped`）也丢题 | 铅笔三条（P1 数对只剩一处落点、P2 格子只剩一个搭档、P4 落点共格锁定）刷到不动点，卡住才一层反证，**再卡住就交出唯一解里的一块** |

每道的规则文案就在 `js/puzzles/<玩法>.js` 的 `rules` 里，首页 `?` 按钮弹的就是它。

> **数邻的口径要说死，不许糊**：这一款**不承诺纯逻辑可解**。本轮重跑（每档 40 张出货盘，seed 串
> `probe|<档>|<i>`；探针是工作区根的 `_tmp-dominosa-readings.mjs`，不在仓里，任何一颗 seed 都能按同一
> 量法重跑；跑的时候本机 load ~7）只用铅笔三条就推满全盘的比例是
> **95% / 60% / 40%**（4×5 / 6×7 / 8×9）—— 也就是 8×9 那档**十张里有六张推不完**，必须靠一层反证，
> 反证也收不住的剩下的块就交给"答案"那一级。同一轮在单测 fuzz 那套 seed（`fuzz|<档>|<i>`，各 40 张）上是
> **90% / 48% / 35%**，两个口径都摆在这儿，取低的看也不好看。
> 再记一条覆盖缺口：提示阶梯最后那一级"交出唯一解的一块"在这两套各 120 张（合计 240 张）盘里
> **命中 0 次** —— 反证那一级都收住了。它现在只由 `test/dominosa.test.mjs` 里一张**手摆的 2×3 盘**
> （三条铅笔与一层反证都判不出哪种切法活）单独覆盖，生成器路径上目前**没有实测样本**。
> 出题这一侧本轮实测：三档 120 张盘的数解预算一次都没烧穿（`cappedTries` 合计 0），墙钟/张 p50/p95 是
> 0.12/0.35 · 0.26/1.70 · 8.22/25.4 ms（8×9 最大一张 55 ms）。

## 引擎契约

外壳只管路由、计时、记分和输入设备无关性；棋盘内部的一切属于引擎。十一套引擎实现
同一个契约（[`js/puzzles/CONTRACT.md`](js/puzzles/CONTRACT.md)）：

- `generate(seed, sizeKey) → spec` 是纯函数，`spec` 必须能 `JSON.stringify`；
- `create(spec) → engine` 是不碰 DOM、不读时钟、不采样随机数的状态机；
- 同一个 seed 在任何设备上是同一道题 —— 每日挑战靠这个才成立；
- `moves` 单调累加：撤销不退款。评星因此测得出"人在试错"，洗不掉；
- `par` 必须是可证的下界，不能是拍脑袋的目标数；
- `hint()` 真的落子，不是弹一句话。

加一道新玩法 = 一个引擎文件 + `registry.js` 里三处（import、`SHELL` 一条、`KINDS` 末尾一个）
+ `tools/playtest.mjs` 里一条 PLAN 和一段"该怎么点"，最后 `index.html` 那个每日题数占位由
`test/registry.test.mjs` 钉着与 `KINDS.length` 同数。第十一款（数邻）就是照这张单子接的。

## 已验证

`bash tools/verify.sh` 在本地跑通，输出即下面这些数字；同一份脚本每次 push 都在
GitHub Actions 的 4 核 ubuntu runner 上再跑一遍（`.github/workflows/ci.yml`），红了就在
CI 的 check-run 注解里点名是哪一条 —— 单测的命令要写成 `test/*.test.mjs`：把目录交给
node 22 的 test runner，它一个文件都找不到，却只报一条名为 "test" 的失败，看起来像
"测试跑了没通过"，其实是一道都没跑。

- **259 项引擎单测**（`node --test test/*.test.mjs`）。能配独立参照的地方都配了一份对拍：
  点灯的 GF(2) 消元 vs 枚举 2^(n²) 个按压力集的暴力；孔明棋的位图 DFS vs 用 `Set`
  重写一遍的朴素搜索 —— 连"证明死局"的集合大小都要相等；数墙 / 帐篷 / 黑白 / 隔离 /
  五寸钉各带一份只照白话规则数一遍的 `bruteOk`，与引擎判定互不引用（五寸钉那份是从
  格子四角反推的邻接表，外加 3×3 全部 512 张盘的枚举数解对拍）；数间那份自己枚举矩形、
  自己判胜、自己做精确覆盖数解数，与引擎的候选池、位掩码、规则层三方对拍，还用两块手搓
  盘把解数钉死（2×2 对角两个 2 天生两解、3×3 那一盘一格都盖不住所以零解）。数织从空盘做纯线推理
  能一路推到图形，这既是唯一性证明也是"不必猜"的保证；数链的构造解另用 `countSolutions`
  独立枚举复核一遍唯一性；数邻那份 `myCheck` 只照白话数一遍（铺满、每块是相邻两格、每个无序
  数对恰好一次），`myCount` 把全盘所有骨牌铺法穷举出来再筛，与引擎的候选池、传播层、数解器
  互不引用，另用三张手摆的 2×3 盘把"两解 / 一解 / 铅笔与反证都收不住"三种情形钉死。
- **注册表测试**（`test/registry.test.mjs`）：每个玩法声明的每个档位都真能出题、能开、
  能画、能给提示，`par` 在引擎和题面两处必须是同一个数，每日挑战的档位要轮得到每一档；
  另两条是接第十一款时补的 —— **加玩法不许改动别人的排期**（其余十款 28 天的档位序列逐字节钉死，
  接线前跑出来的读数当黄金），以及 **README / package.json / index.html 报的玩法数量必须等于
  `KINDS.length`**（接第十一款之前，前两个门面的那个数还停在四、README 停在十；这条严到连提历史都不许用"几种玩法"的句式写）。
- **92 项无头复验**（`tools/playtest.mjs`，CDP `Input` 域；本轮实跑 `rows: 92 fail: [] errors: []`）。
  真 `mousePressed/Moved/Released` 打到画布上，十一种玩法各从第一格一路点到结算屏：判胜、星级、
  存档、HUD 全走 live 路径。另覆盖键盘光标、真点击撤销、宽屏与 390×720 手机视口、每日种子、
  零控制台错误。数邻那八条里，横着的骨牌由"按住拖过两格"落子、竖着的由"点两下"落子，副笔那道
  界线也是两下真 `pointerdown` 划出来的（引擎门口的探针记到 `btn=1` 且成交才算过，10 块 = par 10
  步、零提示三星 —— 划那道线不收账，这条顺带就验了）。
- 数学事实钉在用例里：25 孔小十字"满盘缺中心"**可证无解**（两边都跑到穷尽，214749 个
  局面全进死局集），33 孔英式同一条开局**可解**；37 孔法式同一条开局给 80 万节点也
  烧不完，于是求解器如实返回 `capped = true` —— 预算烧完不等于证明无解。
