# 设计说明

读者是要改这套代码的人。这里只写"看文件看不出来"的那部分：为什么这么切层、
几条不显然的口径、以及踩过的坑。逐条接口定义在
[`js/puzzles/CONTRACT.md`](../js/puzzles/CONTRACT.md)。

## 一条主线：可复现

`generate(seed, sizeKey)` 是纯函数，`spec` 能 `JSON.stringify`，引擎不读时钟、
不采样未播种的随机数、不碰 DOM。这条约束换来三件实打实的东西：

1. 每日挑战不需要服务器 —— 同一天在所有设备上是同一套题，唯一的排题处是
   `js/puzzles/registry.js:47` 的 `dailySpec`（首页和路由两条入口都得走它，否则玩家会拿到
   和进度条不一样的题）。
2. 求解器可以当测试用 —— 单测里那句"独立暴力实现和引擎在 5000 个局面上判定相同"
   之所以稳定，是因为双方拿到的是同一个位图。
3. 存档只需要存记号，不需要存答案。

引擎里出现的 `nowMs()` 只服务动画时间戳与判胜时刻，不参与任何判定；判胜一律看
盘面本身（`litCount === total`、`pegs === 1`、`clueMatch()`）。

## 分层

```
js/main.js          装配 + window.nikoli（无头复验的唯一入口）
js/ui/app.js        路由、计时、记分、评星、键盘 —— 设备无关的输入都在这层收敛
js/ui/board_view.js 格坐标 ↔ 画布像素的唯一换算处；指针事件 → 整数格
js/puzzles/*.js     每道玩法一个文件：题面、状态机、渲染
js/core/            rng / storage / audio / paper / theme
```

`BoardView` 只认 `engine.board = {cols, rows, margin}` 和 `down/move/up/draw`。
所以"数织能拖拽、孔明棋只能两点成一段"这种差别留在引擎里，外壳一行都不用改。
`margin` 用格做单位（数织左侧要留 clue 的宽度），于是 `layout()` 不需要知道任何
玩法的形状。

## 口径：`moves` 是账，不是盘面

十一家统一：**撤销不回退 `moves`，重做也不另收一次**。快照只搬盘面，不搬账。
理由很实际 —— 如果撤销能退款，"步数 ≤ 基准 × 1.2" 这第三颗星就变成"手速够快地
试出来"，测不出人是否在试错。`par` 因此必须是可证下界，不能是拍脑袋的目标数：

- 数织 `par` = 必须涂黑的格数（每次 `down`/`move` 至多涂一格）；
- 数链 `par` = `n²`（经典规则要铺满，一格一次落子）；
- 点灯 `par` = GF(2) 上全部解里的最短按压数；
- 孔明棋 `par` = 起始子数 − 1（每跳必吃一子，所以任何一局通关都是最优解，
  跟着提示走天然能拿满三星）；
- 数墙 `par` = 唯一解的墨格数（"一块岛一数字、不重复用"把墨量钉成一个可加的账）；
- 帐篷 `par` = 行线索之和，也就是唯一解里的帐篷数；
- 黑白 `par` = 题面之外的格数（每格都欠一手）；
- 隔离 `par` = 唯一解里的黑格数；
- 五寸钉 `par` = `n²`（每格都要落一条斜线，一次落子至多定下一格）；
- 数间 `par` = 盘上的数字个数（一笔只能围出一间，而每间都得有人围一次）；
- 数邻 `par` = 骨牌张数 `k(k+1)/2`，正好是盘格数的一半（一笔落一块、一块两格，而每张骨牌
  都得有人落一次）。

`par` 的单位是"一子"，而各家的一子不一样大：数织是一格、点灯是一次按、数间是一笔框住
四格、数邻是一块两格的骨牌。所以"一笔画四格"在数间里就是一步 —— 这也是它 `moves` 能恰好等于 `par` 的原因。

记号一律不计账：数织的叉、数墙的圆点、帐篷/黑白的叉、隔离与五寸钉的小标记、数邻副笔那道
「不许配对」的界线都是"人给自己留的备忘"，不是盘面状态。所以 `moves` 数的是落子，不是点击次数 ——
`test/registry.test.mjs:68` 的 `par` 断言会验一遍"报了 par 的引擎，两处那个数必须相等"。

## 求解器不许说谎

三处刻意的设计，都各有用例钉着：

- **`capped` 与"无解"分开**。孔明棋的 DFS 有节点预算，预算烧完只能报
  `solvable: null, capped: true`。换一种候选顺序重跑，不能把没搜完洗成搜完了 ——
  这条曾经真就错过一次（每一序开头重置 `capped`），现在测试里正面写着。
- **生成器不返回 `null`**。严格趟找不到合格的题就松开门槛再找一趟，并在 `spec` 上
  留 `degraded: true`（数链/孔明棋/隔离走这条）；数墙与帐篷另有冻在代码里的真题盘，
  五寸钉退回满标数盘，数邻退回 `frozenSpec` 里那三张手抄真题（每张都当场用 `countSolutions`
  重新数过、解取自它的 witness，不是"抄下来的盘应该没问题"）—— 总之兜底交出去的也得是一道能判胜的真题。
  外壳拿到 `null` 只能崩给玩家看，那比一道偏易的题糟得多。
- **提示真的落子**。`hint()` 改状态并返回 `{cells, note}`；推不出来返回 `null`，
  由外壳说"这条路堵住了"，而不是硬编一句安慰。
- **数邻把"求解器"分成四件事，各不借谁的力**。`propagate`（P1 数对只剩一处落点 / P2 格子只剩
  一个搭档 / P4 数对落点共格锁定，只下"在任何解里都成立"的结论）、`logicSolve`（空盘刷到不动点，
  推满全盘就顺带证明唯一）、`countSolutions`（带节点预算的分支计数，是唯一性的保险丝；
  `capped` 的盘**当场丢掉**，绝不拿半截计数当证据）、`validate`（不搜索，照白话规则直接数一遍：
  覆盖成不成块、数对齐不齐）。判胜走 `validate` 那套数法，出题复核走 `countSolutions`，
  提示只认 `propagate` 与一层反证 —— 单测里另有一份谁都不 import 的 `myCheck`/`myCount` 对拍。
  它的"答案"那一级照 `spec.count` 选词：数过"恰好一种"的盘才敢说"唯一解"，其余如实说"不止一种切法"。

## 只有测了才看得见的坑

- **从同一个哈希上切位段做轮转**。每日挑战原本这样挑档位：把日期串折成一个 `h`，
  再按玩法序号取 `h >> (i * 3)`。看起来人畜无害，实际是七个玩法在 28 天里一次都没
  换过尺寸 —— 日期串只有末两位在变，高位段天天一样，而 `i * 3` 恰好切在那些不动的
  位上；`i` 一大还会整体右移出界。现在每个玩法各自哈希整颗种子（`js/core/rng.js:5` 的 `hashSeed`），
  位段之间不再互相借位。回归闸门是 `test/registry.test.mjs:112` 的 `never`："28 天内每个档位
  都轮到过、且没有一档吃掉 75% 以上"。
- **难度锚点要先量它会不会动**。五寸钉靠"删多少数字"调难度，第一版拿"推导写入了
  多少格"当尺子，实测才发现这个数对任何可推到底的盘恒等于 `n²` —— 一把尺子量不出
  差别，就等于没有。真正会动的是收敛遍数（6×6 实测 3..6..11、10×10 是 5..9..17）
  和规则加权分（几乎不动，48..52，只配用来打破平手）。所以挑题按遍数排序。
  教训通用：**先量分布，再挑那个铺得开的当主尺**，别凭"它听起来像个难度指标"下锅。
- **只用拖动完成的玩法，键盘必须另有一条路**。外壳的光标键位只发"按下立刻抬手"，从不发
  `move`；数间第一版因此出现"一格宽的一间谁也围不上"—— 那一笔的起点和终点是同一格，
  在旧手势里等于什么都没发生。现在原地抬手算"钉一个角"，第二下定对角，拖动仍然一票成交。
  两边都各有一条断言钉着：单测走两下、无头复验走真拖动，两条都必须走到 `moves === par`。
  凡是加新玩法的人：**先问自己的手势在键盘上还剩多少表达力**，别等玩家用光标发现画不出来。
  数邻两条手势都留着：横着的骨牌在复验里走"按住拖过两格"，竖着的走"点两下"（同一条路也就是
  键盘光标那两条 `down`）。**它有一处已知不齐**：`move()` 不认笔 —— 在副笔模式下按住拖到邻格，
  落的是骨牌而不是界线（其余几家的 `down()` 会把这一笔的意图锁住，`move()` 照它继续画）。
  本轮按"副笔语义与文案不一致时改文案、不改引擎"处理：`SHELL.dominosa.tip` 明写"副笔两下"
  并补一句"拖动不算副笔"，复验里那条界线也只发两下 `pointerdown`（探针记到 `btn=1` 且成交才算过）。
  要真修就得给 `move()` 加笔锁并补一条用例，那是引擎的事，记在这儿当下一轮的账。
- **别拿墙钟毫秒当验收线，也别把目录交给 test runner**。这两条都是 CI 红了三次才挖出来的：
  单测里那些"法式最坏 260ms，留 40% 余量"的上界，同一份代码在本机 15 核、能效核（`taskpolicy -b`）、
  CI 那台 4 核（还要并发 11 个测试文件）之间实测差到 30 倍 —— 25 孔小题能从 40ms 涨到 1.2s，
  节点数却一个没多。现在能配工作量的都改按节点数计（`spec.nodes + spec.reverseNodes`；
  25 孔满盘缺中心的全部可达局面就是 214749 个，`nodes === dead` 本身就是"每个都证明是死局"），
  剩下的只留一条"算法塌成指数才碰得到"的保险丝，可证的上界写在档位自己的 tries/audit 里。
  另一半：**正确性测试里不该有计时行** —— 40 颗种子的唯一解对拍挂掉，原因居然是机器忙。
  而 `node --test test/` 在 CI 的 node 22 上一个文件都找不到，只报一条名为 `test` 的失败
  （本机 node 26 同样写法 237 条全跑），看起来是"测试没通过"，其实是一道都没跑。

## 已知的数学事实（别拿去当题）

- 25 孔小十字"满盘缺中心"**可证无解**：引擎与独立参照都跑到穷尽（`capped === false`，
  214749 个局面全进死局集）。
- 33 孔英式同一条开局**可解**，约 1 万节点。
- 37 孔法式同一条开局给 80 万节点**烧不完** → 只能报 `capped`。所以法式档的题一律
  由倒放生成给出，绝不把"经典开局"当题面挂出去。
- 数间的**数字之和必须等于格数**（每块铺满一次、面积各答其数），差一个的盘天生无解，
  `createBoard` 当场就喊。这条账还能反着用：合并邻块时限制在档位自己的 `maxArea` 之内，
  否则 10×10 会被合成几间超大块、`par` 掉到 9 而显得"很简单"。
- 两块**人眼可数**的手搓盘钉在用例里：2×2 对角各一个 2 天生两解（横切竖切都成，永远
  不能出题）；3×3 里 `2 0 2 / 0 3 0 / 0 0 2` 那一盘，左下角那格没有任何合法矩形盖得住，
  于是一间候选都没被杀掉却零解 —— 传播层必须报 `dead`，不能报"推完了"。
- 数邻另有三张**2×3 手摆盘**（只有 1-1 / 1-2 / 2-2 三张骨牌，肉眼数得清）：一张天生两解
  （绝不能出题）、一张恰好一解、一张三条铅笔加一层反证都判不出哪种切法活 —— 最后那张是提示
  阶梯"答案"级唯一的实测覆盖。**生成器交出的三档 120×2 张盘里没有一张逼到过那一级**，这条缺口
  写在 `test/dominosa.test.mjs` 的头注释与 README 里，不当它已经覆盖。

## 布局：内容不能反过来撑容器

`layout()` 读 `wrap` 的尺寸、写画布的尺寸。一旦 `wrap` 的高度是由画布撑出来的，
就接上了一个反馈环：画布变大 → wrap 变高 → ResizeObserver 重排 → 画布更大。
宽屏那版用 `flex-wrap` 排 `#play`，`#board-wrap` 独占一行且交叉轴被内容决定，正好
踩中：落子中途坐标一路漂移，后半程的点击落到隔壁格甚至画布外，而单测全绿 ——
只有 live 指针事件才暴露得出来。现在宽屏是 `grid` + `minmax(0, 1fr)`，棋盘行只跟
容器要高度；复验里"全程画布尺寸不漂移"就是这条的回归闸门。

顺带一个 CSS 权重坑：`.screen[hidden] { display: none }` 压不住 `#play { display: grid }`，
所以规则写成 `#play:not([hidden])`。

## 无头复验为什么用真指针事件

`tools/playtest.mjs:400` 走 CDP 的 `Input` 域发 `mousePressed/Moved/Released`，而不是在
页面里 `dispatchEvent` 造合成事件。差别在于：前者会真的走命中测试、坐标换算和
`setPointerCapture`，而这三处正是上面那个漂移 bug 的藏身处。页面侧只留读状态的
辅助函数（`geom/settle/steps/report`）和一个在引擎门口记一笔的探针，没有任何绕过
判定的后门。

每个格子都重新量一次几何，并且等它稳定（`settle()`）再落子 —— 因为 HUD 文案一变长，
控制行就会换行，画布随之重排。这不是为了迁就测试而写的补丁：它就是"人在窄屏上边看
边点"的真实情形。
